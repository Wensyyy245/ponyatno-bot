# ПОНЯТНО — бот, который объясняет домашку, а не списывает её

Присылаешь фото задания или текст — получаешь разбор по шагам: что дано, как решать,
почему именно так, ответ, вопрос на самопроверку и похожую задачу для тренировки.
Плюс проверка своего решения, лимиты, PRO за Telegram Stars, донаты и рефералка.

Аудитория: школьники 5–11 классов в РФ и их родители.

## Честно о режимах

| Режим | Что умеет | Нужен ключ |
|---|---|---|
| **AI** | читает фото, понимает текстовые задачи по смыслу, объясняет «проще», проверяет чужое решение | да |
| **Офлайн** | примеры, линейные и квадратные уравнения, проценты, дроби; алгоритмы 20+ типовых заданий по 11 предметам | нет |

Бот **запускается и приносит пользу без ключа**: математика считается полностью офлайн,
по остальным предметам выдаются алгоритмы решения. Фото — только с ключом.

## Запуск

**Windows, самый простой способ:** двойной клик по `start.bat`.
Он сам находит рабочий Python, при необходимости ставит зависимости и запускает бота.

Вручную (если `python` в системе живой):

```powershell
cd ponyatno-bot
py -3 bot.py
```

`.env` уже создан с токеном. База появится в `data/ponyatno.sqlite3` при первом старте.

### Если не запускается

Сначала одно действие: **двойной клик по `check.bat`**. Он проверяет всё по пунктам
(Python, библиотеки, `.env`, токен, Telegram, Stars, ключи AI) и говорит, что сломано.

| Ошибка | Причина | Что делать |
|---|---|---|
| `Сбой выполнения программы python.exe: The system cannot find the path specified` | двойной клик по `bot.py` или `python` в PATH — битая заглушка Microsoft Store | запускать `start.bat`; вручную — `py -3 bot.py`. По желанию свяжи `.py` с настоящим Python (без прав админа): `reg add "HKCU\Software\Classes\.py" /ve /d "Python.File" /f` и `reg add "HKCU\Software\Classes\Python.File\shell\open\command" /ve /d "\"%LOCALAPPDATA%\Python\pythoncore-3.14-64\python.exe\" \"%1\" %*" /f` |
| `UnicodeDecodeError: 'utf-8' codec can't decode byte 0xff` | `.env` сохранён в UTF-16 (Блокнот → «Unicode») | уже не падает: конфиг читает UTF-16/UTF-8/BOM сам. Всё равно лучше пересохранить в UTF-8 |
| `TelegramConflictError: Conflict: terminated by other getUpdates request` | запущено два экземпляра бота | второй экземпляр теперь отсекается файловой блокировкой `data/bot.lock` и пишет «Бот уже запущен в другом окне» |
| `PermissionError: [WinError 5] Отказано в доступе: 'data'` | `DB_PATH` был относительным и создавался в текущем каталоге запуска, а не в папке проекта | исправлено: относительные пути считаются от папки проекта, а если писать некуда — база уезжает в `%LOCALAPPDATA%\Ponyatno`. Диагностика показывает, где лежит база |
| `BOT_TOKEN не задан` | пустой `.env` или токен в кавычках/с BOM | вписать `BOT_TOKEN=123456789:AAH...` без кавычек |
| `ModuleNotFoundError: No module named 'aiogram'` | зависимости не стоят в этом интерпретаторе | `start.bat` поставит сам, либо `py -3 -m pip install -r requirements.txt` |
| вместо русского — `?????` / кракозябры | консоль не в UTF-8 | запускать через `start.bat` (там `chcp 65001`); вручную — `chcp 65001` |
| окно закрылось мгновенно | ошибка до запуска | `check.bat` не закрывается и показывает причину; полный трейсбек — в `data/last_error.log` |

Один токен = один запущенный процесс. Второй экземпляр всегда упирается в конфликт,
поэтому блокировка стоит прямо в коде.

### Что делает запуск надёжным

* `start.bat` сам находит рабочий Python (`py -3` → `python` → пользовательская установка),
  ставит зависимости, включает UTF-8 и держит окно открытым при ошибке.
* `bot.py` проверяет версию Python и наличие библиотек **до** импорта aiogram и вместо
  трейсбека печатает, что именно поставить.
* Файловая блокировка `data/bot.lock` не даёт запустить второй экземпляр.
* Любое падение пишется целиком в `data/last_error.log` — этот файл можно просто прислать.
* База и блокировка ищут свободное место сами: папка проекта → `%LOCALAPPDATA%\Ponyatno` →
  `%TEMP%\Ponyatno`. Если проект лежит на Desktop, в OneDrive или в защищённой папке,
  бот не упадёт с `WinError 5`, а просто будет хранить данные в другом месте.
* Пути из `.env` (`DB_PATH`) считаются от папки проекта, а не от текущего каталога —
  поэтому `start.bat` работает из любого места, даже из `C:\Windows\System32`.
* Накопившиеся сообщения не выбрасываются: если человек нажал `/start`, пока бот лежал,
  он получит ответ после запуска.

## Ключ AI (чтобы заработало фото)

1. Возьми любой OpenAI-совместимый доступ: ProxyAPI, VseGPT, OpenRouter или свой шлюз.
   Для РФ проще ProxyAPI или VseGPT — оплата картой РФ.
2. Впиши в `.env`:
   ```
   AI_BASE_URL=https://api.proxyapi.ru/openai/v1
   AI_API_KEY=sk-...
   AI_MODEL=gpt-4o-mini
   ```
3. Перезапусти бота. В `/start` появится «🤖 Разбор по фото включён».

Модель должна уметь изображения (`gpt-4o-mini`, `gpt-4o`, `qwen-vl-max` и аналоги).
Если модель текстовая — фото вернёт ошибку, текст продолжит работать.

## Ключи: пул и авто-ротация

Ключей можно держать сколько угодно — они переживут отказ любого из них.

* `.env`: `AI_API_KEY=...` (основной) и `AI_API_KEYS=sk-1,sk-2,sk-3` (остальные).
* `keys.txt`: по одному ключу на строку — для массовой проверки.
* Проверка всех ключей настоящим запросом: `python probe_keys.py`
  (живые остаются, мёртвые удаляются из `keys.txt`, рабочий ключ прописывается в `.env`).
* При старте бот делает один дешёвый запрос (`healthcheck`) и сразу выключает мёртвые ключи:
  обещания «фото включено» без рабочего ключа не будет.
* Во время работы: `401/403` → ключ в карантин на 6 часов и берётся следующий;
  `429` → ключ остывает 90 секунд; три ошибки подряд → карантин.
  Состояние живёт в `data/keys_state.json` (там только хэши, не сами ключи).
* Если живых не осталось — бот не падает, а уходит в офлайн-режим.
* Служебное: команда `/keys` (только для `ADMIN_ID` из `.env`) показывает состояние пула.

Проверить конкретно свой ключ: `python liveai.py` (текст + тестовое фото с уравнением),
`python find_model.py` (какая модель с картинками реально отвечает).

### Подключить любой свой шлюз одной командой

```powershell
python set_provider.py https://api.ваш-сервис.ру/v1 gpt-4o-mini sk-вашключ
```

Скрипт проверит ключ настоящим запросом к модели и только при успехе запишет
`AI_BASE_URL`, `AI_MODEL`, `AI_API_KEY` в `.env` и сбросит карантин ключей.
Если не сработало — `.env` не тронет и скажет, что ответил сервер.

### Ranvik — ключ рабочий, дело в балансе (на 2026-11-16)

Сервис из скриншота — **Ranvik**: `https://api.ranvik.ru/v1`, кабинет
`https://api.ranvik.ru/dashboard/api-keys`, ключи вида `rk_live_...`.

* Ключ `rk_live_6m…OPam` **принимается**: `/v1/models` отдаёт 200 и 231 модель,
  из них 112 с поддержкой изображений.
* Любой запрос к модели возвращает:
  `402 insufficient_quota: insufficient funds: balance non-positive: 0.00 ₽ (top up to continue)`
* То есть ключ верный, но **баланс API — 0 ₽**. Цифра $500 в кабинете относится
  к другому счётчику (или к другому ключу — в кабинете «Мои ключи 1 / 2»).

Что сделать после пополнения баланса (или если у второго ключа есть средства):

```powershell
python set_provider.py https://api.ranvik.ru/v1 gemini-2.5-flash <ваш-ключ>
```

Скрипт проверит реальный ответ модели и только тогда запишет `.env`. Если у второго
ключа есть баланс — подставь его. Модель с картинками: `gemini-2.5-flash`,
`gpt-4.1-mini`, `gpt-4.1` (в каталоге Ranvik есть и другие).

### Статус на 2026-11-16

Все присланные ключи проверены настоящим запросом к модели (публичный `/models`
для этого не годится — он отвечает 200 даже на мусорный ключ). Результат:

| Ключ | Ответ провайдера |
|---|---|
| `sk-1qm…ZER6` (первый) | OpenAI `401 Incorrect API key`, OpenRouter `401 not an OpenRouter key`, ProxyAPI `401 Invalid API Key`, VSEGPT `400 not found` |
| 48 ключей вида `sk-abcd1234…` | то же самое — `401` у всех |
| `sk-ogfd…jnB1` (новый) | OpenAI `401 Incorrect API key`, ProxyAPI `401`, VSEGPT `400 not found` |
| `rk_live_6m…OPam` (новый) | Replicate `401 Unauthenticated` — и это токен Replicate, он вообще не про чат-модели |

Рабочих ключей нет, они удалены из `.env` и `keys.txt`. Бот работает в офлайн-режиме:
математика, проценты, уравнения и алгоритмы по 11 предметам — работают, фото включится,
как только в `.env` появится рабочий ключ.

Что означают префиксы:

* `sk-proj-...` — ключ OpenAI (нужен `AI_BASE_URL=https://api.openai.com/v1`, из РФ напрямую не работает);
* `sk-or-v1-...` — ключ OpenRouter (`AI_BASE_URL=https://openrouter.ai/api/v1`);
* у ProxyAPI и VSEGPT ключи выдаются в личном кабинете, формат свой;
* `rk_live_...` — Replicate, для фото-разбора не годится: у него нет OpenAI-совместимого чата.

Как проверить новый ключ, не запуская бота:

```powershell
python probe_keys.py     # проверит и сам впишет рабочий ключ в .env
```

Бот больше не пишет «ключ не вписан», если ключи вписаны, но отклонены: он показывает
ответ провайдера и подсказывает команду проверки.

## Монетизация

Магазин разделён на три отдельных входа — это не «тарифы», а три разных товара:

| Кнопка | Что продаёт | Цена |
|---|---|---|
| **🎟 Купить запросы** | штучные разборы, не сгорают | 20 — 99 ⭐ · 50 — 199 ⭐ · 100 — 349 ⭐ |
| **♾ Подписка** | безлимит разборов на срок | 30 дней — 499 ⭐ · 90 дней — 1199 ⭐ |
| **💛 Поддержать администрацию** | просто поддержка проекта, без доступа | 25 / 50 / 100 / 250 ⭐ или своя сумма |

Логика доступа:

* **Каждый день бесплатно начисляется 3 запроса** (не «пробный период», а ежедневное
  пополнение — сгорает только дневной остаток, купленные запросы не сгорают).
* Списывается сначала бесплатный дневной остаток, потом купленные запросы.
* Подписка отключает счётчики полностью: `solves_left()` возвращает `None` и списаний нет.
* Донат доступ к продукту не даёт — так честнее и понятнее, чем «донат = бонус».

### Рефералка: +5 запросов за друга, подписанного на канал

Ссылка `t.me/<бот>?start=ref_XXXXXX`. Друг заходит, подписывается на канал и жмёт
«Я подписался» — бот проверяет подписку через `getChatMember` и начисляет
**+5 запросов** пригласившему (ровно один раз за друга).

Настройка в `.env`:

```
CHANNEL_ID=@ваш_канал        # или -100… ; бот должен быть админом канала
CHANNEL_URL=https://t.me/ваш_канал
```

Если `CHANNEL_ID` пустой, проверка пропускается и бонус начисляется сразу после перехода —
удобно, пока канала нет. Если бот не админ канала, `getChatMember` вернёт ошибку,
и бот честно скажет «не могу проверить подписку».

Технически: `send_invoice` с `currency="XTR"`, `provider_token` не передаётся.
Payload: `req:<uid>:<пакет>`, `sub:<uid>:<тариф>`, `don:<uid>:<звёзды>`.
`pre_checkout_query` сверяет и uid, и сумму. Повторное начисление защищено проверкой
`telegram_payment_charge_id` в таблице `payments`.

## Приватность и границы

* Фото не сохраняются: скачиваются в память, уходят в AI и удаляются. В базе — только
  предмет, класс, режим и время.
* Бот объясняет, но не пишет сочинения и проекты целиком — и говорит об этом в интерфейсе.
* В разборах бывают ошибки: в ответе всегда есть блок «Проверь себя».
* Токен и ключ — только в `.env`, он в `.gitignore`. Токен, отправленный в чат или
  на скриншоте, считается скомпрометированным: перевыпусти через `/revoke` у @BotFather.

## Деплой на VPS

```bash
sudo apt install python3-venv -y
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
```

`/etc/systemd/system/ponyatno.service`:

```ini
[Unit]
Description=PONYATNO bot
After=network.target

[Service]
WorkingDirectory=/opt/ponyatno-bot
ExecStart=/opt/ponyatno-bot/venv/bin/python bot.py
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now ponyatno
journalctl -u ponyatno -f
```
